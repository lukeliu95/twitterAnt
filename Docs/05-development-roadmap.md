# Money Signal 开发路线图

## 项目概览

**Money Signal** 是一个从 Twitter 发现赚钱机会的浏览器插件。本文档详细规划了从 MVP 到正式产品的完整开发路径。

---

## Phase 1: MVP 验证（2 周）

### 目标

验证核心价值假设：「能否自动发现有价值的赚钱机会」

### 范围

#### Week 1: 基础设施搭建

**Chrome 插件基础**
- [ ] 项目初始化（Vite + CRXJS + React + TypeScript）
- [ ] Manifest V3 配置
- [ ] Content Script 框架
- [ ] Background Service Worker 框架
- [ ] 基础消息通信

**推文提取**
- [ ] DOM 监听器实现
- [ ] 推文数据提取
- [ ] 推文去重逻辑
- [ ] 本地关键词初筛

**后端基础**
- [ ] Fastify/Hono 项目初始化
- [ ] PostgreSQL 数据库搭建（Supabase）
- [ ] Prisma ORM 配置
- [ ] 基础 API 路由（接收推文）

#### Week 2: 核心功能实现

**推文分析**
- [ ] Claude API 集成
- [ ] 简单的 Prompt 模板
- [ ] 单个推文分析流程
- [ ] 信号评分逻辑

**结果输出**
- [ ] Telegram 机器人发送结果
- [ ] 每日定时任务（推送 Top 3 信号）
- [ ] 基础的错误处理和重试

**测试验证**
- [ ] 本地端到端测试
- [ ] 小范围内测（5-10 人）
- [ ] 收集反馈和统计数据

### 不做

- 不做用户系统
- 不做精美 UI
- 不做多 Agent 协作
- 不做向量检索

### 验证指标

| 指标 | 目标 |
|-----|------|
| 每日采集推文数 | > 100 条 |
| 有效信号率 | > 10% |
| 用户满意度 | > 3/5 |

## 风险与应对

### 技术风险

| 风险 | 影响 | 概率 | 应对 |
|-----|------|------|------|
| Twitter DOM 变化 | 高 | 高 | 多备选选择器 + 监控告警 |
| Claude API 不稳定 | 中 | 中 | 备用模型 + 重试机制 |
| 成本超支 | 中 | 中 | 优化调用次数 + 分级定价 |

### 产品风险

| 风险 | 影响 | 概率 | 应对 |
|-----|------|------|------|
| 信号质量不稳定 | 高 | 中 | 用户反馈驱动优化 |
| 用户不活跃 | 高 | 中 | 提高推送精准度 |
| 隐私顾虑 | 中 | 低 | 明确隐私政策 + 本地优先 |

## 成功指标

### 北极星指标

**每周活跃信号行动率**
- 定义：每周有「已行动」反馈的用户数 / 活跃用户数
- 目标：> 20%

### 关键指标

| 指标 | Phase 1 | Phase 2 | Phase 3 |
|-----|---------|---------|---------|
| DAU | 10 | 100 | 500 |
| 信号/天 | 10 | 50 | 200 |
| 行动率 | 5% | 15% | 25% |
| 留存率(D7) | 20% | 40% | 60% |
| NPS | 20 | 40 | 50 |
